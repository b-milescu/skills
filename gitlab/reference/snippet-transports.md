# GitLab snippet transport contracts

Stable `/gitlab` snippet names are workflow API. This file is the human-readable transport contract for each snippet: MCP primary tool(s), required inputs, outputs, fail-closed checks, guarded `glab` fallback conditions, and post-mutation MCP re-read requirements. Active workflow snippets name MCP-native tools/contracts.

Machine-actionable source truth: `skill://gitlab/reference/snippet-metadata.json`. Markdown table is checked against this metadata by `tests/gitlab-snippet-metadata.sh`.

## Global rules

- **Transport order:** MCP first, guarded `glab` fallback second, local `git` only for local worktree/branch/default-branch safety.
- **Safe text:** Run `validate_gitlab_text` or an MCP safe text mutation tool before body-bearing MR/issue description/note mutations. Diagnostics must name role/offset only and must not print body secrets.
- **Decision-grade reads:** Prefer `get_merge_request_workflow_snapshot` for guard-grade MR state/SHA. Use body-free `get_merge_request(include_description:false)` only for required fields absent from the snapshot. Read descriptions and individual note bodies separately through their dedicated bounded MCP readers. Prefer other single-record MCP reads (`get_project`, `get_issue`, `get_pipeline`) over list data; `list_*` results are candidate data unless narrowly scoped and complete enough for the decision.
- **Post-mutation re-read:** After MCP or fallback mutation, re-read through MCP to check project, target IID, head SHA when applicable, and intended state before reporting success.
- **Fallback evidence:** When fallback is used, record transport evidence `via=glab-fallback`; MCP primary actions record `via=mcp`. Fallback never bypasses reviewed-SHA, exact-candidate Gate Receipt, authority, caller identity/token-stability, context-firewall, content-byte, or Mutation Guard order. CI status is advisory.
- **GitLab Mutation Guard:** Every snippet with non-empty `allowed_mutations` follows project binding, target re-read, reviewed SHA, exact-candidate Gate Receipt when relevant, advisory CI observation, authority verification, caller identity/context, safe text, fallback eligibility, exactly one mutation, and post-mutation MCP re-read; machine schema: `skill://gitlab/reference/mutation-guard.schema.json`.

## Known MCP gaps fallback limits

- **Merge robustness (`mcp_merge_robustness_gap`):** one live smoke fixture observed `merge_merge_request` report/error-normalization weakness for `Branch cannot be merged` while equivalent SHA-bound `glab mr merge` succeeded. Use fallback only after Mutation Guard fresh target re-read, reviewed SHA, exact-candidate Gate Receipt, authority, caller identity, and fallback-eligibility phases pass.
- **List pagination (`mcp_pagination_gap`):** exposed `list_*` tools currently do not show reliable pagination controls to agents. Treat broad lists as incomplete; narrow filters, single-record reads, and guarded fallback may identify candidates, but single-record MCP re-read must decide before any mutation.
